Setup & Troubleshooting Guide

Everything on this page was written by actually setting PhenoFusion3D up on blank machines — a factory-fresh Ubuntu 20.04, a WSL2 distro, and a Windows 11 laptop with a discontinued L515 LiDAR camera — and recording every failure and its fix.

On this page

Linux setup — Ubuntu 20.04, zero friction

One idempotent script takes a completely blank Ubuntu 20.04 LTS install (including WSL2) to a verified, working app. It needs no pre-installed runtimes — not even Python. 

git clone https://github.com/PhenoFusion-3D/PhenoFusion3D.git
cd PhenoFusion3D
chmod +x setup.sh
./setup.sh                    # base install (GUI + reconstruction, no camera)
./setup.sh --with-realsense   # + Intel librealsense2 SDK + pyrealsense2
./setup.sh --l515             # + L515-compatible pyrealsense2 (<2.55)
./setup.sh --with-ros         # + ROS Noetic base for the gantry backend
./setup.sh --verify-only      # re-run just the verification step

What the script does, in order:

StepDetail
Python 3.10–3.12Uses any suitable interpreter already on PATH; otherwise apt-installs one via the deadsnakes PPA — but only after confirming apt can actually see the package (focal is past EOL, so PPA coverage is checked, not assumed); otherwise downloads a standalone CPython 3.11 via uv with no sudo at all.
Native librariesInstalls the full Qt xcb / xkb / X11 / OpenGL / EGL runtime set that a fresh Ubuntu lacks — the libraries whose absence causes the classic "Could not load the Qt platform plugin xcb" crash.
Virtual environmentCreates .venv-linux/ with --system-site-packages so a system-installed rospy stays importable. Reused if already valid; rebuilt if broken.
Project installpip install -e . (editable), plus optional extras per flag.
OpenCV/Qt conflict fixSwaps opencv-python for opencv-python-headless — the bundled cv2 Qt plugins otherwise hijack PyQt5's platform plugin path and abort the GUI at startup.
VerificationImports every dependency, spins up a headless QApplication, and runs an Open3D point-cloud smoke test. Ends with VERIFICATION PASSED.
sudo: required only for the apt steps; the script invokes it itself and passes DEBIAN_FRONTEND=noninteractive through sudo so nothing (looking at you, tzdata) can stall a fresh install waiting for keyboard input. Running as root works too.

Launch after setup:

source .venv-linux/bin/activate
python main.py

Proving it on a pristine machine

"Works on my machine" isn't verification. The setup script is validated by importing a factory-fresh Ubuntu 20.04 root filesystem as a throwaway WSL distro — ships with Python 3.8 only, so it exercises the entire cold path — running the script, and checking for the verification banner: 

# PowerShell
mkdir C:\wsl -Force
curl.exe -LO https://cloud-images.ubuntu.com/focal/current/focal-server-cloudimg-amd64-root.tar.xz
wsl --import PhenoTest C:\wsl\PhenoTest .\focal-server-cloudimg-amd64-root.tar.xz --version 2
wsl -d PhenoTest

# inside the blank distro
git clone https://github.com/PhenoFusion-3D/PhenoFusion3D.git ~/PhenoFusion3D
cd ~/PhenoFusion3D && bash setup.sh

# afterwards, throw the test distro away
wsl --unregister PhenoTest

Windows setup

For development and camera sanity-testing on Windows 10/11:

git clone https://github.com/PhenoFusion-3D/PhenoFusion3D.git
cd PhenoFusion3D
py -3.11 -m venv venv
.\venv\Scripts\Activate.ps1
pip install -e ".[windows]"
.\launch.bat

launch.bat exists because managed Windows machines often have Get-ExecutionPolicy = AllSigned, which refuses unsigned .ps1 scripts. The .bat wrapper bypasses policy for that single invocation without changing any persistent machine setting.

L515 LiDAR camera — end-of-life hardware

Intel discontinued the L515 in August 2021 and dropped its enumeration from librealsense in releases ≥ 2.55. A default pip install pyrealsense2 today gets a version that physically cannot see an L515, even when Windows shows the camera healthy on the USB bus. Three hard constraints follow:

ConstraintConsequence
Last compatible SDK is 2.54.2Install with the [l515] extras group, which pins pyrealsense2>=2.54.0,<2.55.
2.54 wheels exist only for Python ≤ 3.11Use Python 3.10 or 3.11, not 3.12+.
WSL2 has no USB passthrough by defaultThe L515 is a Windows-native device for this project; launch from PowerShell, not WSL.
py -3.11 -m venv venv
.\venv\Scripts\Activate.ps1
pip install -e ".[windows,l515]"
.\launch.bat

On startup main.py runs a self-check that detects all three traps — running under WSL, missing pyrealsense2, and an SDK too new for the L515 — and explains the exact fix in a dialog before you click Capture. A healthy launch prints: 

[startup] pyrealsense2: 2.54.2.5684
[startup] RealSense devices visible: 1
[startup]   - Intel RealSense L515 (fw 1.5.8.1, USB 3.2)

Troubleshooting — real failures, real fixes

Every entry below is a failure we actually hit while bringing machines up.

SymptomCause & fix
qt.qpa.plugin: Could not load the Qt platform plugin "xcb" in .../cv2/qt/plugins, then Aborted (core dumped) opencv-python bundles its own Qt which hijacks PyQt5's plugin path. Fix: pip uninstall -y opencv-python && pip install opencv-python-headless. setup.sh now does this automatically.
E: Unable to locate package python3.11 on Ubuntu 20.04 Focal is past end-of-standard-support, so PPA package availability can't be assumed. setup.sh checks apt-cache before installing and falls back to an existing interpreter on PATH, then to a standalone uv-managed CPython.
./setup.sh: Permission denied The execute bit was lost (fresh clone on some filesystems, or a re-copy). chmod +x setup.sh, or just bash setup.sh.
Script fails with strange \r / "command not found" errors Windows line endings from editing on the host. Fix: sed -i 's/\r$//' setup.sh.
apt install hangs on a timezone/keyboard prompt mid-script sudo strips DEBIAN_FRONTEND=noninteractive from the environment. setup.sh passes it through sudo explicitly.
"No Intel RealSense camera was found" with an L515 that Windows sees fine pyrealsense2 ≥ 2.55 dropped L515 support. Reinstall with pip install -e ".[windows,l515]" on Python 3.10/3.11. The startup self-check diagnoses this automatically.
Camera works in PowerShell but not from WSL WSL2 does not pass USB through by default. Launch from PowerShell — the app detects WSL and warns before capture. (usbipd-win passthrough was evaluated and rejected: real overhead for a 5 Gbps device with a clean native path available.)
OleInitialize() failed ... RPC_E_CHANGED_MODE at startup on Windows COM apartment ordering: Qt wants STA, librealsense's Media Foundation backend inits MTA. The app creates QApplication first and runs the camera self-check second — if you're modifying main.py, keep that order.
rospy import fails inside the venv on the lab rig ROS wasn't sourced when the venv was created. source /opt/ros/noetic/setup.bash, then re-run ./setup.sh --with-ros — the venv uses --system-site-packages precisely so it can see the system rospy.
AppImage crashes with the xcb plugin error on a fresh host The host lacks X11 client libraries (host requirement, not a build bug). Install the same Qt/X11 set that setup.sh installs — see install/README.md for the one-line apt command.
Verify any install, any platform: every setup path ends with the same check — all imports, a headless Qt QApplication, and an Open3D smoke test. On Linux: ./setup.sh --verify-only. Look for VERIFICATION PASSED.
